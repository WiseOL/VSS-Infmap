Revision 14: retain impact metadata independently of projectile visuals.

Previously, a client impact update was discarded if its projectile effect had
not initialized, was expired, was missing its crate, or was excluded by the
256-projectile visual cap. Ammo such as APHE creates the explosion from that
impact callback, so discarding it could discard the explosion too.

Initial bullet messages now snapshot the crate ammo type/caliber/projectile,
filler and WP masses on the server (supports crate Entity and EntIndex paths).
The client retains at most 2048 lightweight impact records in a ring, for at
most 120 seconds. They are not Lua effect entities. Updates use an existing
projectile when valid, otherwise the retained ammo record and a model-change
stub. Terminal impacts release their records and pending projectile effects;
explicit server removal and expiry clean them too. HEAT detonation state is
carried into a projectile effect if its initialization happens after penetration.
Existing projectile visual limits and expiry remain unchanged.

This repairs an identified loss path, not every possible missing particle.
Missing initial messages, metadata eviction, client particle limits, material
errors or other effect errors can still affect visuals. No explosion damage,
ammo balancing, HUD traces, vehicle physics, or pickup permissions changed.

Replace the combined addon folder, fully restart the server and reconnect.
Map, no-collide/physgun, P2M/performance, RAC/camera/crew fixes remain included.

Mocked tests cover impact before projectile Init, impacts while the cosmetic
projectile budget is full, no additional projectile allocation, duplicate
terminal suppression, server crate-index snapshots and bounded metadata.
Existing effect lifecycle and gun/radar regressions pass. Live-server tests
are required: close APHE/HEAT hits, rapid fire and long flights across chunks.
