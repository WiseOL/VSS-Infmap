REVISION 17 - BALLISTIC MONITOR AND WATER MATERIAL
Replace the previous combined addon folder, fully restart the server and reconnect clients.
Map, existing compatibility fixes and monitor are included.

Run in the superadmin player console or trusted server console:
acf_infmap_ballistics
  Current active bullets, measured ACF milliseconds per server tick, tick-budget percentage,
  observed tick rate and configured thresholds. Allow a second for the first sample.
acf_infmap_ballistics list 20
  List up to 20 bullets with ammo and owner (maximum 100).
acf_infmap_ballistics watch 30
  Stream once per second to a superadmin console for 30 seconds (maximum 60).
acf_infmap_ballistics stop
  Stop watching.
acf_infmap_ballistics limits 8 1000 2 10
  EXAMPLE: reset if average measured time exceeds 8 ms/tick OR active bullets exceed
  1000, sustained for 2 seconds, with at least 10 seconds between automatic resets.
  Choose thresholds from your server measurements. A zero disables that threshold.
acf_infmap_ballistics off
  Disable both automatic thresholds while retaining monitoring.
acf_infmap_ballistics reset
  Remove all current bullets immediately through ACF cleanup; no forced detonation.

Automatic reset is OFF by default. Settings are archived server convars:
acf_infmap_ballistics_max_ms 0
acf_infmap_ballistics_max_count 0
acf_infmap_ballistics_hold 2
acf_infmap_ballistics_cooldown 10

Timing covers inclusive ACF CreateBullet and IterateBullets Lua processing, without
counting nested calls twice. It is not total server CPU time, native physics time,
or a per-player attribution; independently scheduled custom bullet handlers may
not be included. Sampling and cleanup cannot interrupt a blocking function.
Reset preserves ACF's existing bullet table reference, releases indexes and calls
removal callbacks, then clears client visual/pending/impact state in one broadcast.
Callback-created bullets are blocked during cleanup; callback errors are logged
and do not prevent the remaining snapshot from being cleared.

Water surface now uses the supplied Hammer material dev/dev_water2_cheap.
No Workshop download is required for this built-in material. In-game appearance
on InfMap's mesh remains to be verified; buoyancy calculations are unchanged.

Validation: mocked Lua tests passed for permissions, measurement, error recovery,
thresholds, cooldown, table identity, callback failure and bulk client cleanup.
Existing trace/network, collision/chunk/P2M, camera, crew G-force and water tests pass.
Live Garry's Mod server performance and rendering have not been tested here.
