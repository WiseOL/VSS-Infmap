REVISION 26 - PER-ROUND RANGE AND LIFETIME CLEANUP
Replace the old combined addon folder, restart fully and reconnect all clients.
This build adds default-enabled per-bullet guards; overload table resets remain
separate and opt-in. Does not require enabling acf_infmap_ballistics limits.

SERVER CONVARS (archived; also usable in server.cfg):
acf_infmap_bullet_max_age 30
  Maximum real seconds since bullet registration. Zero disables age expiry.
acf_infmap_bullet_max_range 1000000
  Maximum radius in Source units from THAT bullet's launch position, not map
  spawn. Default 1,000,000 units is approximately 25.4km. Zero disables range expiry.
  Example tighter limit: acf_infmap_bullet_max_range 200000 (approximately 5.08km).
acf_infmap_bullet_cleanup_status
  Superadmin/server-console report of active rounds and expiry reason counters.

Before normal ACF flight calculation, checks age and current global position.
Before DoBulletsFlight, also checks NextPos and TraceTo. If either movement or
lookahead endpoint reaches the radius, expires the entire round before that
trace runs. Conservative: this can end a round up to its lookahead length early;
it does not trace up to the boundary or simulate a final hit within that step.
Invalid positions and extremely oversized trace steps are also culled so those
rounds cannot keep issuing pathological chunk traces. Uses no trace-recursion
loop and adds no global trace detour. Gun checks/radar queries are unchanged.

Expiry calls ACF RemoveBullet, releases the bullet index/table entry, and uses
the existing reliable client notification to remove managed bullet visuals,
stop tracer emitters, invalidate pending visual initialization, and clear impact
metadata. Client impact ring slots are now released too, rather than retaining
old metadata until ring replacement. No forced explosion on expiry. Removal
callbacks cannot create replacement bullets during expiry; callback errors are
logged (first three) and do not leave the original table entry alive.

Traces are synchronous queries: there is no persistent trace entity/table to
remove afterward. Removing the round stops future normal flight queries.
Already applied damage, decals, past explosion effects and emitted particles
are not undone. Independently spawned fragments are separate bullets, each
with its own launch origin/age guard; no family-wide recall is implemented.

A 0.25-second sweep covers self-iterated/stalled custom rounds in the ACF bullet
table. Caps sweep removal at 128 per pass to spread bursts. Such custom rounds
can therefore expire later during a backlog; normal flight guards run immediately
when processing resumes. Custom code outside these entry points is only covered
by the sweep. Existing bullets at hot installation get a new registration origin
and age; full server restart avoids that ambiguity.

PERFORMANCE LIMITS
This prevents indefinite accumulation; it does not make thousands of concurrent
simulated rounds free. The inspected VSS fork still has its own 2,000-active-bullet
index limit. This patch does not raise it. Firing thousands over time can recycle
expired indexes, but actual server cost depends on rate, collisions, penetration,
network load and other addons. Use acf_infmap_ballistics watch to measure.

VALIDATION
Mocked server tests cover launch-relative range at distant global coordinates,
pre-trace rejection, age, self-iteration, invalid input/oversized steps, cleanup
callback failure and replacement suppression, index release and bounded expiry
of a 2,000-round burst. Actual compatibility client receiver tests confirm expiry
notification clears pending visuals, impact lookup and ring slot reference.
Existing scoped trace, compact networking/effect and overload-monitor tests pass.
No live Garry's Mod stress test or zero-lag claim.

Includes all prior combined map/ACF/Water/Wire compatibility changes.
