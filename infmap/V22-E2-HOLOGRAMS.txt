REVISION 22 - ORIGINAL E2 HOLOGRAM SCRIPT SUPPORT
Replace the previous combined addon folder, restart fully and reconnect clients.
Use your original HSbyHoloH MPTF A2 E2 unchanged. No E2 replacement is required.
Wiremod remains a separate installed dependency.

The installed Wiremod holoPos implementation calls WireLib.setPos, which clamps
global XYZ coordinates to +/-16384 before InfMap sees them. A hologram moving
with a distant chip therefore receives the wrong global target. The new server
bridge bypasses only that global pre-clamp for gmod_wire_hologram on InfMap.
Unparented holos use InfMap SetPos normally. Parented holos use the physical root
chunk and the native SetPos API, preserving the parent's coordinate frame when
the target itself lies across a canonical chunk boundary. Native coordinates
still pass Wire's clamp: huge parent-relative distances remain engine-limited.
Angles, scale, alpha, ownership/index validation, E2 code and Gate parenting are
untouched. No generic trace, Wire entity positioning, or physics changes here.

Module: lua/autorun/server/infmap_wire_holograms.lua
Startup log: [Wire InfMap] E2 hologram global positioning installed.
Only installs with InfMap/Wire ready; bounded startup retries, no per-frame scan.

Validation: actual installed WireLib clamp/setPos and E2 holoPos bodies executed
with mocked Source transforms. Tests pass global positive/negative XYZ positions,
parent/root chunk use, stale intermediate metadata, boundary offsets, root rebase,
invalid numeric input, missing hologram index, cycle bound, native bounds,
non-hologram isolation and no installation on ordinary maps.
Live HSbyHoloH Gate motion, client rendering and dupe integration need in-game
verification. This fixes the identified positioning clamp/frame issue; it does
not change Source parent-distance limits or promise all Wire hologram features.

Includes the combined map plus all v21 buoyancy/tool, waterjet, material and ACF fixes.
