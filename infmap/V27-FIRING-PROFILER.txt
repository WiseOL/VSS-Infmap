REVISION 27 - FIRING PROFILER
Replace the old combined addon folder, restart fully and reconnect.
Includes previous v26 per-bullet lifetime/range guards and all earlier fixes.
This revision measures firing cost; it does not claim a new speed improvement.

SERVER (superadmin player console or trusted server console):
acf_infmap_profile start 30
  Capture 30 seconds, automatically finish and save JSON.
acf_infmap_profile status
acf_infmap_profile stop
  Finish early and save current capture. Duration range is 1-120 seconds.
Only one server capture at a time; no per-frame scans or trace timers when idle.
Client captures are separate and not started by the server command.

CLIENT (your own game console):
acf_infmap_client_profile 30
  Capture render frame durations and peak managed bullet visuals/pending effects.
  Saves JSON on that client. Measures the entire scene, not ACF GPU time alone.

TEST PROCEDURE
1. Capture a quiet baseline on the same map/location for 30 seconds.
2. Run both commands again, then reproduce heavy firing for the window.
3. Keep ammo/guns, player count, viewing direction and duration comparable.
4. Send the quiet and firing server_firing_*.json files from the SERVER's
   garrysmod/data/infmap/ and, if FPS is affected, the corresponding
   client_firing_*.json from your CLIENT's garrysmod/data/infmap/.
Reports have timestamp plus a serial suffix to avoid same-second overwrite.

SERVER MEASUREMENTS
- Inclusive ACF CreateBullet/IterateBullets Lua time per observed engine tick.
- Scoped chunk trace total time and nested raw engine trace time, recorded only
  during captures. Includes gun, radar and camera scope, not only projectiles.
- Trace/segment/cross-chunk counts, created bullets, sampled active bullet peak.
- Compact/generic effect and individual bullet removal packet counts; encoded
  compatibility bytes. Does not multiply by recipients or include transport,
  retransmission, full-reset broadcasts or all server networking.
- Observed ticks/second and engine-wide last physics-step samples each second.

INTERPRETATION
Ballistic and trace timings overlap. Raw trace time is nested inside total trace
 time; do not add these values. Physics is engine-wide, not attributed to ACF.
A large trace/raw gap may point to chunk conversion/filter overhead. High raw
trace cost suggests collision work. High ballistic cost with little trace cost
suggests simulation/penetration/custom callbacks, but requires deeper profiling.
The report cannot isolate fragments or every individual ammo callback yet.
Encoded bytes are a payload measure, not actual per-player bandwidth.
Client FPS changes alone cannot prove bullet effects are the cause; compare the
same scene and record effect counts. Worst frame is not a percentile.

Capture instrumentation adds timing overhead. Counters do not alter collision
results, bullet cadence, damage, network recipients, visual limits or overload
settings. Peak bullet count is sampled, so very short peaks may be missed.
No guarantee of lag-free thousands-of-round simulation; live captures are needed
before selecting further optimizations or compromising simulation accuracy.

TESTS
Server/client profiler tests pass permissions, valid duration, overlap rejection,
cumulative-counter deltas, per-tick units, samples, manual finish/flag restore,
report saving and client frame/effect reporting. Actual chunk trace wrapper tests
confirm raw/total timing only while enabled. Scoped trace/network/effect cleanup
and ballistic monitor regressions pass. Mocked APIs; no live load test performed.
